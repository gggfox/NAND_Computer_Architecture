# Glossary

Terms used across code, issues and docs. Use these names; avoid the listed synonyms.

- **NAND**: the only built-in logic primitive. Every other logic chip is built from NANDs.
- **Chip**: a reusable component with input pins and output pins. Either built-in (NAND, clock, I/O) or custom.
- **Custom chip**: a chip the user builds from other chips and saves with a name and color. _Avoid_: component, module, block.
- **Circuit**: the wiring inside a chip that the user edits on the canvas. _Avoid_: board, schematic.
- **Pin**: a connection point on a chip. Input pins receive signals; output pins drive them.
- **Wire**: a connection from one output pin to one or more input pins.
- **Signal**: the value on a pin or wire at a given tick (high/low). When routing, a signal is its source pin plus bit plus wire colour: wires of one signal may share a route, wires of different signals never overlap.
- **Tick**: one step of the simulation. Every NAND takes one tick to update its output.
- **Built-in part**: a non-logic primitive (input pin, output pin, clock, later displays).
- **Bit width**: how many bits a pin or wire carries. Part of the file format from v1; the v1 UI only exposes 1-bit.
- **Project**: a named collection of custom chips. The unit of export, import and sharing.
- **Fork**: a copy of a shared project that becomes the recipient's own. _Avoid_: clone, duplicate.
- **Theme**: a named set of design tokens (colors, etc.) applied to both UI and canvas.
- **Action**: a typed, named description of one edit to a project (place chip, connect wire, rename...). The only way state changes. _Avoid_: command, mutation, event.
- **Folder** / **Tag**: user-defined ways to organise chips in the chip library. Folders nest to any depth; a chip is in at most one folder, and a chip whose folder is missing shows at the top level. A tag is free text, and a chip can have several.
- **Built-in folder**: the fixed first folder of the library, listing the built-in parts (NAND, Split, Merge). It can't be renamed, moved or deleted.
- **Move to…**: the row menu item that files a chip or moves a folder by picking a folder from a list. The keyboard and screen-reader way to do what a drag does.
- **Seed**: the number that decides how races resolve. Saved with the project; same seed + same inputs = same result. _Avoid_: random state.
- **Race**: two or more gates changing on the same tick in a way where the outcome depends on which "wins".
- **Saved version** / **Draft**: a chip's published circuit (what users of the chip run) and its in-progress edits. _Avoid_: published/unpublished, version 2.
- **Unsaved changes**: a draft that differs from its saved version in its pins, parts, wire ends, wire colours or hand bends; automatic routes don't count. Shown by a dot next to the chip's name in the chip header, and on the chip's library row. On its library row, a never-saved chip shows its "Draft only" badge instead; the header shows the dot for it. _Avoid_: dirty.
- **Save confirmation**: the dialog a save opens when it would drop wires in the chips that use the chip, listing the wires removed in each and the pins that caused it. A save that drops no wire saves at once. Not the same as the first save's folder dialog.
- **Breadcrumb trail**: the chip path in the chip header, from the chip first opened down through each "Look inside" to the open chip. Tapping an earlier chip goes back to it without saving. A reload keeps only the open chip. _Avoid_: stack, history.
- **Pins panel**: the list of a chip's inputs and outputs where names, widths and order are edited. Its order is the only pin order. A side panel on wide screens, a bottom sheet on phones.
- **Bit tap**: a wire end attached to one bit of a multi-bit pin.
- **Pin piece**: the canvas piece of one of the chip's own input or output pins.
- **Tidy pins**: rebuild the input and output columns, anchored at each column's first pin, in panel order. One undo step.
- **Order badge**: the small number on a pin piece showing its place in the Pins panel.
- **Step (clock)**: one toggle of the clock followed by a settle.
- **Split** / **Merge**: built-in parts converting between one n-bit pin and n 1-bit pins.
- **Library**: the browsable sheet/panel of chips (search, starred, folders, tags). **Quick-add menu**: the long-press/right-click menu that places a chip at the press point.
- **Armed placement** (placing): a chip or part picked in the library so that every tap on the canvas places a copy, until Escape, a tap on its row, or "Done" in the placing banner. Arming it disarms an armed pin, and the other way round. Not an edit; each part placed is one. _Avoid_: stamp mode.
- **Recent**: the last five kinds placed in this session, offered first in the quick-add menu. Not saved.
- **Tool**: what a one-finger drag on empty canvas does: Pan or Select. A session preference, not an edit. A drag on a chip always moves it.
- **Selection**: the chips (and the wires between them) the user has picked on the canvas. Not an edit, so undo skips it.
- **Selection bar**: the row of Duplicate, Array…, Delete and Pick pins shown while chips or pins are selected, docked at the top centre of the canvas (bottom on phones). Duplicate, Array… and Delete show only with chips selected. _Avoid_: floating toolbar.
- **Duplicate**: copies the selected chips, and the wires between them, one grid step down and to the right, as one undo step. It leaves the clipboard alone. Not a copy of a project: that is a fork.
- **Array**: copies the selection several times in a row, column or grid, from a dialog, as one undo step. The copies aren't wired to each other.
- **Pin selection**: an ordered list of whole pins picked for a bulk wire, in the order they were added. Part of the selection, so it lives outside undo history. Its order decides which pin gets which bit. _Avoid_: pin set.
- **Pick pins**: the selection bar toggle that makes a plain tap on a pin add it to the pin selection, or remove it. The touch way to do what `Shift`+tap does.
- **Reading order**: top to bottom by pin anchor, then left to right, then instance order. "Select this pin on all selected chips" adds pins in reading order, so an Array's pins come row by row. Not the same as canvas order, which `]`/`[` use and which follows instance order.
- **Bulk wire**: wiring every pin in the pin selection to one source pin, as one undo step. A same-width source fans out; a wider source is wired bit by bit, selected pin k to bit k. It is all or nothing: one illegal wire refuses the lot and names the first offending pin.
- **Marquee**: the box or lasso being drawn to select chips. A chip is picked when its centre is inside.
- **Pin card**: the small card showing a pin's name, width and live value.
- **Chip menu**: the menu of actions on a chip (Delete; for custom chips Rename chip, Recolour chip, Look inside).
- **Camera**: the canvas's zoom and offset. Kept in the URL when at rest.
- **Minimap**: the small overview in the canvas corner; a tap or drag centres the camera.
- **Probe**: a signal whose level the engine reports to the main thread so pins and wires show live levels.
- **Armed pin**: the pin picked as the start of a wire; the next tap on a legal pin connects to it. Not an edit.
- **Bit picker**: the small menu of legal bits (`d0`...) shown when a 1-bit pin is wired to a bus and the bit is not yet chosen.
- **Trunk**: the stretch of route that wires of the same signal share, drawn once.
- **Junction**: the dot where a branch leaves a trunk.
- **Tidy wires**: re-route every automatic wire in the open chip from scratch. The only time the router moves wires an edit did not touch.
- **Wire colour**: one of eight named colours (blue, red, orange, yellow, green, teal, purple, pink) a wire can carry, or the default. On wires are full colour, off wires muted and dashed.
- **Bend mode**: editing one wire's bends by dragging a handle on each segment, or with `]`/`[` and the arrow keys. Not an edit until a bend moves.
