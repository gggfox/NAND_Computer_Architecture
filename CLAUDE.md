## Commands

- `pnpm dev`: start the Vite dev server.
- `pnpm build`: production build. SPA shell is emitted at `dist/client/_shell.html`, then the service worker is generated.
- `pnpm preview`: serve the production build locally.
- `pnpm check`: the full gate (typecheck, lint, stylelint, format check, knip, spell, lint canaries, tests). CI and pre-push run it.
- `pnpm typecheck`: regenerates Paraglide output and CSS module types, then `tsc --noEmit` (TypeScript 7 native). Needs `src/routeTree.gen.ts`, which is committed and regenerated by `dev`/`build`.
- `pnpm test`: Vitest with coverage thresholds. `pretest` and `prelint` run `pnpm i18n`, so both commands work on a fresh clone.
- `pnpm e2e`: Playwright on all projects except `@visual`, against the production build.
- `pnpm e2e:visual:docker`: visual snapshots inside the Linux Playwright image. Baselines are Linux-only; never commit macOS ones.
- `pnpm format`: oxfmt write. `pnpm format:check` verifies.
- `pnpm i18n` (Paraglide compile), `pnpm css-types` (CSS module typings), `pnpm tokens` (regenerate theme CSS from token data).

Notes: the React Compiler runs via `@rolldown/plugin-babel` + `reactCompilerPreset()` in `vite.config.ts`. `verbatimModuleSyntax` stays off per TanStack Start guidance. Dependency versions live only in `pnpm-workspace.yaml` catalogs. Deploy examples are in `deploy/`.

## Subagents

Usage limits are tight, so this overrides skill defaults (including subagent-driven-development's "Model Selection"). Always pass `model` explicitly; an omitted model inherits Opus.

- Implementers and fix agents: `sonnet`. Escalate to `opus` only after a Sonnet agent fails the same task twice.
- Reviews: one review per PR on `sonnet`, not one per task. The final whole-branch review may use `opus`.
- Exploration, search, digests: `haiku` or `sonnet`.
- `opus` subagents only for architecture or design questions, and say why in the dispatch.
- Keep each agent's task small (1-3 files). Agents run focused checks (`pnpm vitest run <files>`, one e2e spec) and pipe long output through `tail`; only the last step runs `pnpm check`.
- At most 2-3 agents at once. Start a fresh session (or `/compact`) per phase instead of one long orchestrator session.

## Rules

- Features expose only `index.ts`; no cross-feature internals; `simulation` imports no React/DOM; `shared` imports no feature; no cycles ([ADR 23](docs/adr/0023-feature-folders.md)).
- `throw` is banned in `simulation` (except `adapters/`) and `domain/`; return `Result` ([ADR 28](docs/adr/0028-result-type-and-error-unions.md)).
- Zod only at trust boundaries ([ADR 27](docs/adr/0027-zod-at-trust-boundaries.md)); only `src/shared/ui` imports react-aria ([ADR 26](docs/adr/0026-react-aria-behind-own-ui-layer.md)).
- Every user string goes through Paraglide in `en` and `es` ([ADR 17](docs/adr/0017-i18n-english-and-spanish.md)).
- Lint, hooks and CI enforce the rules; do not bypass hooks ([ADR 13](docs/adr/0013-ci-and-pre-commit-enforcement.md)). `main` is protected: `check`, `e2e`, `visual` must pass ([ADR 35](docs/adr/0035-protected-main.md)).
- The build stays host-neutral and static ([ADR 18](docs/adr/0018-host-neutral-static-build.md)).
